## 1. *args and **kwargs

### Why do we need them?
When we don't know how many arguments a function will receive!

### Problem without args/kwargs:
```python
def add(a, b):
    return a + b

add(1, 2)        # works
add(1, 2, 3)     # ERROR! too many arguments
```

### *args — unlimited positional arguments:
```python
def add(*args):
    print(args)        # args is a TUPLE
    return sum(args)

print(add(1, 2))           # 3
print(add(1, 2, 3))        # 6
print(add(1, 2, 3, 4, 5))  # 15
```

### What happens internally:
```
add(1, 2, 3, 4, 5)
→ args = (1, 2, 3, 4, 5)  ← tuple!
→ sum((1,2,3,4,5)) = 15
```
*args collects all positional arguments into a TUPLE!

### **kwargs — unlimited keyword arguments:
```python
def display_info(**kwargs):
    print(kwargs)      # kwargs is a DICT
    for key, value in kwargs.items():
        print(f"{key}: {value}")

display_info(name="Sakthi", age=25, city="Chennai")
```

### Output:
```
{'name': 'Sakthi', 'age': 25, 'city': 'Chennai'}
name: Sakthi
age: 25
city: Chennai
```
**kwargs collects all keyword arguments into a DICTIONARY!

### Using both together:
```python
def mixed(a, b, *args, **kwargs):
    print(f"a={a}, b={b}")
    print(f"args={args}")
    print(f"kwargs={kwargs}")

mixed(1, 2, 3, 4, 5, name="Sakthi", city="Chennai")
```

### Output:
```
a=1, b=2
args=(3, 4, 5)
kwargs={'name': 'Sakthi', 'city': 'Chennai'}
```

### Order must always be:
```python
def func(normal, *args, **kwargs):
#         ↑        ↑       ↑
#      regular  positional keyword
#      params   extras    extras
```

### Practice (written today):
```python
def student_info(name, age, *args, **kwargs):
    print(f"Name: {name}")
    print(f"Age: {age}")
    print(f"Subjects: {', '.join(args)}")
    for key, value in kwargs.items():
        print(f"{key}: {value}")

student_info("Alice", 20, "Math", "Science",
             DOB="1990-01-01", Phone=1234567890)
```

### Real world connection — Decorator:
```python
def logger(func):
    def wrapper(*args, **kwargs):
    #            ↑       ↑
    #    captures ALL arguments
    #    passed to original function

        print(f"{func.__name__} starting...")
        result = func(*args, **kwargs)
        #             ↑       ↑
        #    passes them to original function
        return result
    return wrapper
```
Now you know EXACTLY why wrapper uses *args, **kwargs!
It captures and passes through any arguments the
original function needs!

### Key points:
- *args → tuple of positional arguments
- **kwargs → dictionary of keyword arguments
- Order: normal params → *args → **kwargs
- Names args/kwargs are convention, * and ** matter!

### Interview Answer:
"*args allows a function to accept any number of
positional arguments — collected into a tuple. **kwargs
allows any number of keyword arguments — collected into
a dictionary. Used when number of arguments is unknown.
In decorators, wrapper uses *args/**kwargs to capture
and pass through all arguments to the original function."

## 2. Collections Module

### What is the Collections module?
Built-in Python module with special data structures
that make code cleaner and faster.

### 3 most important ones:

---

### Counter — count frequencies instantly:
```python
from collections import Counter

# Count characters
text = "hello world"
count = Counter(text)
# Counter({'l':3, 'o':2, 'h':1, 'e':1, ' ':1...})

# Count list elements
nums = [1, 2, 3, 1, 2, 1, 4]
count = Counter(nums)
# Counter({1:3, 2:2, 3:1, 4:1})

# Most common
print(count.most_common(2))
# [(1,3), (2,2)] → top 2

# Most common word
words = ["apple", "banana", "apple",
         "cherry", "banana", "apple"]
wc = Counter(words)
print(wc)               # Counter({'apple':3,...})
print(wc.most_common(1)) # [('apple', 3)]
print(wc.most_common(2)) # [('apple',3),('banana',2)]
```

### Counter for Valid Anagram — ONE LINE!:
```python
from collections import Counter

def isAnagram(s, t):
    return Counter(s) == Counter(t)

print(isAnagram("anagram", "nagaram"))  # True
print(isAnagram("rat", "car"))          # False
```

---

### defaultdict — dictionary with default value:
```python
from collections import defaultdict

# Normal dict — KeyError if key missing!
normal = {}
normal["a"] += 1  # KeyError!

# defaultdict — never KeyError!
dd = defaultdict(int)   # default value is 0
dd["a"] += 1            # works! a=1
dd["b"] += 1            # works! b=1
dd["c"] += 5            # works! c=5
print(dict(dd))         # {'a':1, 'b':1, 'c':5}

# defaultdict with list
dd_list = defaultdict(list)
dd_list["fruits"].append("apple")
dd_list["fruits"].append("banana")
dd_list["veggies"].append("carrot")
print(dict(dd_list))
# {'fruits': ['apple', 'banana'], 'veggies': ['carrot']}
```

### Old HashMap pattern vs defaultdict:
```python
# Old way
count[char] = count.get(char, 0) + 1

# With defaultdict — cleaner!
count = defaultdict(int)
count[char] += 1
```

---

### deque — double ended queue:
```python
from collections import deque

# Normal list — slow O(n) from front
lst = [1, 2, 3]
lst.insert(0, 0)   # slow! shifts everything

# deque — fast O(1) from both ends
d = deque([1, 2, 3])
d.append(4)        # add right  → [1,2,3,4]
d.appendleft(0)    # add left   → [0,1,2,3,4]
d.pop()            # remove right → [0,1,2,3]
d.popleft()        # remove left  → [1,2,3]
```
Used in BFS problems — you already know BFS!

### Collections Summary:
| Class | Use case | Key method |
|---|---|---|
| Counter | Count frequencies | most_common() |
| defaultdict | Safe dictionary | No KeyError |
| deque | Fast queue | appendleft, popleft |

### Interview Answer:
"The collections module provides specialized data
structures. Counter counts element frequencies and
has most_common() method. defaultdict provides a
default value when key is missing — avoids KeyError.
deque allows O(1) append and pop from both ends —
useful for BFS and sliding window problems."

## 3. LeetCode — Maximum Subarray (Kadane's Algorithm)

### Problem:
Given integer array, find subarray with largest sum
and return that sum.
```
Input:  [-2, 1, -3, 4, -1, 2, 1, -5, 4]
Output: 6
Reason: [4, -1, 2, 1] = 6
```

### Approach — Kadane's Algorithm:

### Core idea:
At each position ask:
"Is it better to extend current subarray OR start fresh?"
Pick whichever gives LARGER sum!

### Real life analogy:
Walking and collecting money. At each spot:
- If carrying negative total → START FRESH
- If carrying positive total → KEEP GOING

### Two choices at every step:
```
Choice 1 → current + num  (extend — keep going)
Choice 2 → num            (fresh — start over)
Pick the BIGGER one!
```

### When to start fresh:
```
When current sum is NEGATIVE → dragging us down!
Example:
current = -3, num = 5
extend → -3+5 = 2  (negative dragged us down)
fresh  → 5         (better! start fresh)
```

### When to extend:
```
When current sum is POSITIVE → helping us!
Example:
current = 3, num = -1
extend → 3+(-1) = 2  (still positive, keep going)
fresh  → -1           (worse!)
```

### Solution:
```python
class Solution:
    def maxSubArray(self, nums):
        current = nums[0]    # current subarray sum
        maximum = nums[0]    # best sum seen so far

        for num in nums[1:]:
            current = max(num, current + num)
            maximum = max(maximum, current)

        return maximum
```

**Time Complexity:** O(n)
**Space Complexity:** O(1)
**Result: ACCEPTED ✅**

### Full Dry Run:
```
nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
current = -2, maximum = -2

num=-2 → current=max(-2,-2+(-2))=max(-2,-4)=-2  max=-2
num=1  → current=max(1,-2+1)=max(1,-1)=1        max=1
num=-3 → current=max(-3,1+(-3))=max(-3,-2)=-2   max=1
num=4  → current=max(4,-2+4)=max(4,2)=4         max=4
num=-1 → current=max(-1,4+(-1))=max(-1,3)=3     max=4
num=2  → current=max(2,3+2)=max(2,5)=5          max=5
num=1  → current=max(1,5+1)=max(1,6)=6          max=6
num=-5 → current=max(-5,6+(-5))=max(-5,1)=1     max=6
num=4  → current=max(4,1+4)=max(4,5)=5          max=6

Answer = 6 ✅
```

### Verified mentally (your example):
```
[1, -2, 3, 6, -1] → answer = 9 ✅
Subarray [3, 6] = 9
```

### Key insight:
```
current = max(num, current + num)
#              ↑         ↑
#         start fresh   extend
```

### Common mistake — don't forget:
Each step uses UPDATED current from previous step!
```
num=-2 → current becomes -1
num=3  → uses -1, not original value!
```

### Patterns learned so far:
```

```

## Interview Questions and Answers

**Q: What is the difference between *args and **kwargs?**
A: *args collects unlimited positional arguments into
a tuple. **kwargs collects unlimited keyword arguments
into a dictionary. Used when number of arguments is
unknown at function definition time.

**Q: What is Counter in Python?**
A: Counter is a dictionary subclass from collections
module that counts element frequencies. It has
most_common() method to get most frequent elements.
Useful for frequency counting problems in LeetCode.

**Q: What is Kadane's Algorithm?**
A: Kadane's algorithm finds maximum subarray sum in
O(n) time. At each position it decides whether to
extend current subarray or start fresh — picks
whichever gives larger sum. Tracks running current
sum and global maximum sum simultaneously.

**Q: When would you use defaultdict over regular dict?**
A: When you need a default value for missing keys to
avoid KeyError. defaultdict(int) defaults to 0,
defaultdict(list) defaults to empty list. Cleaner
than using dict.get() with default values everywhere.
