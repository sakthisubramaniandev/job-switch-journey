## 1. Balanced Binary Tree (LC 110)

### What is a Balanced Tree?
A tree where for EVERY node:
```
|height(left) - height(right)| <= 1
```
Left and right sides cannot differ by more than 1!

### Visual:
```
Balanced ✅:
        1
       / \
      2   3
     /
    4
Left height=2, Right height=1
Difference=1 ← OK!

Not Balanced ❌:
        1
       /
      2
     /
    3
Left height=2, Right height=0
Difference=2 ← NOT OK!
```

### Approach:
```
Combines two things:
1. Max Depth (from Day 014!)
2. Check condition at each node

At every node:
1. Find height of left subtree
2. Find height of right subtree
3. If difference > 1 → NOT balanced!
4. Return -1 as signal for unbalanced!
```

### Why return -1 as signal?:
```
Normal height → always positive number
-1            → special signal meaning
               "somewhere below is unbalanced!"
               -1 bubbles up to root
               root sees -1 → return False!
```

### Solution:
```python
class Solution:
    def isBalanced(self, root):
        def height(node):
            # base case
            if not node:
                return 0        # empty = 0 height

            # get heights of children
            left = height(node.left)
            right = height(node.right)

            # if either child unbalanced → propagate -1
            if left == -1 or right == -1:
                return -1

            # if THIS node unbalanced → signal -1
            if abs(left - right) > 1:
                return -1

            # return height of this node
            return 1 + max(left, right)

        return height(root) != -1
```

**Time Complexity:** O(n)
**Space Complexity:** O(h)
**Result: ACCEPTED ✅**

### Dry Run:
```
Balanced tree:
        1
       / \
      2   3
     /
    4

height(4) = 1
height(2):
  left=1, right=0
  |1-0|=1 ≤ 1 ✅
  return 1+max(1,0) = 2

height(3) = 1

height(1):
  left=2, right=1
  |2-1|=1 ≤ 1 ✅
  return 1+max(2,1) = 3

height(root) = 3 != -1 → True ✅
```

### Unbalanced dry run:
```
        1
       /
      2
     /
    3

height(3) = 1
height(2):
  left=1, right=0
  |1-0|=1 ✅
  return 2

height(1):
  left=2, right=0
  |2-0|=2 > 1 ❌
  return -1

height(root) = -1 → -1 != -1 is False → False ✅
```

### Interview Answer:
"Check if tree is balanced using modified height
function. Returns -1 as signal for unbalanced subtree.
At each node calculate left and right heights. If
difference > 1 return -1. If either child returns -1
propagate it up. Final answer is height(root) != -1.
O(n) time — visits each node once."

## 2. Diameter of Binary Tree (LC 543)

### What is Diameter?
Longest path between ANY two nodes in the tree.
Path doesn't need to pass through root!

### Visual:
```
        1
       / \
      2   3
     / \
    4   5

Diameter = 3
Path: 4→2→1→3 or 5→2→1→3
```

### Key Insight:
```
At each node:
diameter through this node = left_height + right_height

Why?
Longest path goes DOWN left side
then UP right side (or vice versa)!
left_height + right_height = total path length
```

### Why track globally?:
```
Diameter might not pass through ROOT!
Must check at EVERY node and keep maximum!

Example:
        1
       /
      2
     / \
    4   5

Diameter = 2 (4→2→5)
Doesn't pass through root (1)!
```

### Solution:
```python
class Solution:
    def diameterOfBinaryTree(self, root):
        self.diameter = 0       # track globally!

        def height(node):
            if not node:
                return 0

            left = height(node.left)
            right = height(node.right)

            # update diameter at EVERY node
            self.diameter = max(self.diameter, left + right)

            return 1 + max(left, right)

        height(root)
        return self.diameter
```

**Time Complexity:** O(n)
**Space Complexity:** O(h)
**Result: ACCEPTED ✅**

### Dry Run:
```
        1
       / \
      2   3
     / \
    4   5

height(4) = 1, height(5) = 1

height(2):
  left=1, right=1
  diameter = max(0, 1+1) = 2
  return 1+max(1,1) = 2

height(3) = 1

height(1):
  left=2, right=1
  diameter = max(2, 2+1) = 3 ✅
  return 1+max(2,1) = 3

return self.diameter = 3 ✅
```

### Key difference from Balanced:
```
Balanced  → return -1 as signal
            final: height(root) != -1

Diameter  → track self.diameter globally
            update at EVERY node
            final: return self.diameter
```

### Why self.diameter?:
```python
self.diameter = 0
# Can't use local variable — gets reset each call!
# self.diameter persists across all recursive calls!
```

### Interview Answer:
"Diameter is longest path between any two nodes.
At each node calculate left_height + right_height —
this is the path through that node. Track global
maximum because diameter may not pass through root.
Use self.diameter to persist value across recursion.
O(n) time — visits each node once."

## Interview Questions and Answers

**Q: What is a balanced binary tree?**
A: A tree where for every node the height difference
between left and right subtrees is at most 1.
Check recursively — return -1 as signal for unbalanced.
If height(root) != -1 then tree is balanced.

**Q: What is the diameter of a binary tree?**
A: Longest path between any two nodes. At each node
diameter through it equals left_height + right_height.
Track global maximum since diameter may not pass
through root. Use instance variable to persist across
recursive calls.

**Q: How is diameter different from height?**
A: Height is longest path from node to leaf going DOWN.
Diameter is longest path between ANY two nodes going
through a common ancestor — combines left and right
heights. Diameter can be wider than height.

**Q: Why use self.diameter instead of local variable?**
A: Local variables reset with each recursive call.
self.diameter persists across all calls allowing us
to track the maximum diameter seen at any node
throughout the entire recursion.
