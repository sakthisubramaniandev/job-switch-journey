## 1. Error Handling

### Why Error Handling?
Without it — one error crashes entire program.
With it — program handles errors gracefully and continues.

### Basic Structure:
```python
try:
    # code that might cause error
    result = 10 / 0

except ZeroDivisionError:
    # runs if ZeroDivisionError occurs
    print("Division by zero!")

except ValueError:
    # runs if ValueError occurs
    print("Invalid value!")

except Exception as e:
    # catches ANY other error
    print(f"Something went wrong: {e}")

else:
    # runs if NO error occurred
    print("Success!")

finally:
    # ALWAYS runs — error or not
    print("This always runs!")
```

### When each block runs:
```
Scenario 1 — No error:
✅ try runs
⏭️ except skipped
✅ else runs
✅ finally runs

Scenario 2 — Error occurs:
✅ try runs until error
✅ except runs
⏭️ else skipped
✅ finally runs
```

### Common Python Errors:
| Error | Cause |
|---|---|
| ZeroDivisionError | Dividing by zero |
| ValueError | Wrong value type |
| TypeError | Wrong data type |
| FileNotFoundError | File doesn't exist |
| KeyError | Dictionary key missing |
| IndexError | List index out of range |
| AttributeError | Method doesn't exist |

### Safe Divide (written today):
```python
def safe_divide(a, b):
    try:
        result = a / b
        return result
    except ZeroDivisionError:
        print("You cannot divide a number by zero!")
        return None
    except TypeError:
        print("All the inputs must be numbers!")
        return None
    finally:
        print("Division attempted.")


print(safe_divide(10, 2))      # 5.0
print(safe_divide(10, 0))      # Cannot divide by zero!
print(safe_divide(10, "abc"))  # All inputs must be numbers!
```

### Custom Exceptions:
```python
class InsufficientFundsError(Exception):
    def __init__(self, amount, balance):
        self.amount = amount
        self.balance = balance
        super().__init__(
            f"Cannot withdraw {amount}. Balance is {balance}"
        )


class BankAccount:
    def __init__(self, balance):
        self.balance = balance
    
    def withdraw(self, amount):
        if amount > self.balance:
            raise InsufficientFundsError(amount, self.balance)
        self.balance -= amount
        return self.balance


account = BankAccount(1000)

try:
    account.withdraw(500)
    print(f"Balance: {account.balance}")  # 500
    account.withdraw(800)                  # raises error!

except InsufficientFundsError as e:
    print(e)  # Cannot withdraw 800. Balance is 500
```

"Error handling in Python uses try/except/finally blocks.
try contains code that might fail. except catches specific
errors and handles them gracefully. finally always runs
regardless of error — used for cleanup like closing files
or database connections. Custom exceptions inherit from
Exception class for domain specific errors."

## 2. File Handling

### Basic Operations:
```python
# Writing to file
with open("test.txt", "w") as f:
    f.write("Hello Sakthi!\n")
    f.write("This is line 2\n")

# Reading entire file
with open("test.txt", "r") as f:
    content = f.read()
    print(content)

# Reading line by line
with open("test.txt", "r") as f:
    for line in f:
        print(line.strip())

# Appending to file
with open("test.txt", "a") as f:
    f.write("This is line 3\n")
```

### File Modes:
| Mode | Meaning |
|---|---|
| "r" | Read only (default) |
| "w" | Write (creates new or overwrites!) |
| "a" | Append (adds to existing) |
| "r+" | Read and write |

### Why `with` statement?
```python
# Without with — must close manually!
f = open("test.txt", "r")
content = f.read()
f.close()   # forget this → memory leak!

# With with — closes automatically!
with open("test.txt", "r") as f:
    content = f.read()
# file closed automatically ✅
```
with uses context manager — handles open/close automatically!

### Interview Answer:
"Python file handling uses open() with modes r, w, a.

closes the file using context manager — preventing memory
leaks. Always use try/except with file operations to handle
FileNotFoundError and IOError gracefully."

## 3. LeetCode — Contains Duplicate

### Problem:
Given an integer array, return true if any value
appears at least twice, false if all elements distinct.
```
Input:  [1, 2, 3, 1]  → true  (1 appears twice)
Input:  [1, 2, 3, 4]  → false (all distinct)
Input:  [1, 1, 1, 3]  → true  (1 appears 3 times)
```

### My Solution — HashMap (independent! 🔥):
```python
class Solution:
    def containsDuplicate(self, nums):
        count = {}
        for num in nums:
            count[num] = count.get(num, 0) + 1
            if count.get(num) >= 2:
                return True
        return False
```

**Time Complexity:** O(n)
**Space Complexity:** O(n)
**Result: ACCEPTED ✅**

### Cleaner approach — Set:
```python
class Solution:
    def containsDuplicate(self, nums):
        return len(nums) != len(set(nums))
```

**Why this works:**
```
nums = [1, 2, 3, 1]
set(nums) = {1, 2, 3}  ← removes duplicates!

len(nums) = 4
len(set)  = 3
4 != 3 → True → has duplicates!
```

### All Approaches Compared:
| Approach | Time | Space | Notes |
|---|---|---|---|
| Brute force | O(n²) | O(1) | Two loops |
| HashMap | O(n) | O(n) | Count frequency |
| Set | O(n) | O(n) | Cleanest! |

### Key insight:
Set automatically removes duplicates.
If set length < original length → duplicates exist!

## Interview Questions and Answers

**Q: What is the difference between try/except and if/else?**
A: if/else handles expected conditions in normal flow.
try/except handles unexpected errors and exceptions.
Use if/else for business logic, try/except for error handling.

**Q: What does finally do?**
A: finally block always runs regardless of whether an error
occurred or not. Used for cleanup operations like closing
files, database connections, releasing resources.

**Q: Why use with statement for file handling?**
A: with statement uses context manager which automatically
closes the file when the block ends — even if an error
occurs. Prevents memory leaks and resource wastage.

**Q: What is a custom exception?**
A: A custom exception is a user defined error class that
inherits from Exception. Used to create domain specific
errors with meaningful messages.
